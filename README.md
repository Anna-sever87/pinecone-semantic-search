# Поиск по смыслу: векторная память на Pinecone

Домашнее задание по теме «Архитектуры хранения данных»: настройка индекса Pinecone, подключение embedding-модели, загрузка фраз и поиск по смыслу.

## Что сделано

1. **Pinecone и embedding-модель.** Индекс `hr-facts` (serverless, облако AWS `us-east-1`, размерность 1536, метрика cosine) создаётся из кода. Эмбеддинги строит модель `text-embedding-3-small` через Embedding API OpenAI. Тест `test_embedding.py` показывает вектор из 1536 чисел и сравнивает близость фраз.
2. **Загрузка данных.** 30 фраз о вымышленной компании «Лайм» (отпуск, больничный, зарплата, обучение, удалённая работа, адаптация и другое). Для каждой фразы создаётся вектор, ID `phrase-N`, а в метаданные пишутся текст и тема.
3. **Поиск по смыслу.** 5 запросов, сформулированных другими словами, чем фразы в базе. Для каждого выводятся ID, score и тексты трёх ближайших фраз. Отчёт сохраняется в `results/search_results.md`.

## Схема работы

```
фраза -> Embedding API -> вектор (1536 чисел) -> Pinecone (индекс hr-facts)
запрос -> Embedding API -> вектор запроса -> поиск ближайших векторов (top_k) -> ID, score, текст из метаданных
```

## Выводы

- Поиск идёт по смыслу, а не по словам: запросы «работать из дома», «кто поможет новичку», «документ о том, что я здесь работаю» нашли фразы про удалённую работу, наставника и справку с места работы, хотя таких слов в запросах не было.
- Нужная фраза оказалась на первом месте в 3 запросах из 5, а во всех 5 вошла в тройку лучших.
- В запросах 1 и 5 нужная фраза стоит второй. В запросе 1 на первое место вышла фраза про разделение отпуска (в ней есть «14 календарных дней»), в запросе 5 слово «оплачиваемый» подтянуло фразу про отпуск, а разница с правильной фразой всего 0,0003. То есть эмбеддинги отражают тематическую близость, но не всегда выбирают именно ответ на вопрос.
- Поэтому в боте берут несколько ближайших результатов (`top_k`), а выбрать из них нужное поручают языковой модели.
- Score уменьшается по мере удаления смысла: у вторых и третьих результатов он заметно ниже, чем у лучших совпадений.

## Установка и запуск

1. Зарегистрироваться на pinecone.io и получить API-ключ.
2. Создать виртуальное окружение и установить библиотеки (Windows PowerShell):

```
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

3. Скопировать `.env.example` в `.env` и вписать ключи OpenAI и Pinecone:

```
Copy-Item .env.example .env
```

4. Выполнить по порядку:

```
python test_embedding.py
python load_data.py
python search.py
```

Свои запросы: `python search.py "ваш вопрос" "ещё вопрос" --top-k 5`. Повторный запуск `load_data.py` не создаёт дублей (ID фраз постоянные); `python load_data.py --reset` сначала очищает индекс.

## Настройки (файл .env)

- `OPENAI_API_KEY`, `OPENAI_BASE_URL` - доступ к Embedding API
- `EMBEDDING_MODEL` - модель эмбеддингов (по умолчанию `text-embedding-3-small`)
- `EMBEDDING_DIMENSION` - размерность вектора (1536 для `text-embedding-3-small`; должна совпадать с индексом)
- `PINECONE_API_KEY` - ключ Pinecone
- `PINECONE_INDEX_NAME`, `PINECONE_CLOUD`, `PINECONE_REGION` - имя индекса, облако и регион
- `LOG_LEVEL` - уровень журнала

Ключи хранятся только в `.env`, файл исключён из репозитория через `.gitignore`.

## Ограничения

- Данные учебные и вымышленные (компания «Лайм»).
- Pinecone после записи обновляет статистику с небольшой задержкой, поэтому скрипт загрузки ждёт, пока векторы станут видны.
- Поиск по смыслу не гарантирует, что нужный ответ будет первым: при `top_k=3` в наших запросах он всегда был в тройке, но не всегда на первом месте.
- Размерность индекса должна совпадать с моделью эмбеддингов: при смене модели нужен новый индекс.
